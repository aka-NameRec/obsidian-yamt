# Feature Implementation: Column Width Control

**Date:** 2025-11-10  
**Feature:** Added support for `width` attribute in table cells

## Summary

Implemented the ability to control column widths in YAMT tables by adding a `width` attribute to cell definitions. This attribute accepts any valid CSS width value (px, %, em, rem, vw, auto, etc.).

## Changes Made

### 1. Type Definitions (`src/lib.ts`)

- Added `width?: string` to `NormalizedCell` interface
- Added `width?: string` to `RawCell` type (in both nested object locations)
- Updated `normalizeCellObject()` function to process the `width` attribute

### 2. Rendering (`src/main.ts`)

- Updated `renderRow()` function to apply `width` style to table cells
- Width is applied via `el.style.width = cell.width`

### 3. Documentation

- Updated `README.md` with `width` attribute information and usage example
- Created comprehensive `docs/WIDTH_EXAMPLE.md` with multiple examples:
  - Fixed width columns (px)
  - Percentage width columns (%)
  - Mixed width units
  - Comparison with auto-layout

## Usage Example

```yaml
header:
  - [ 
      { data: "ID", width: "50px" }, 
      { data: "Description", width: "60%" }, 
      { data: "Status" } 
    ]
body:
  - [ "1", "Lorem ipsum dolor sit amet", "✓" ]
```

## Technical Details

### Supported Values

Any valid CSS width value:
- `"50px"` — fixed pixel width
- `"25%"` — percentage of container
- `"10em"` / `"5rem"` — relative to font size
- `"20vw"` — viewport-relative
- `"auto"` — browser default

### Implementation Notes

1. **Backward Compatible**: Width attribute is optional; existing tables work unchanged
2. **Flexible**: Accepts any CSS value as a string, no validation or restrictions
3. **Consistent**: Follows same pattern as existing attributes (`align`, `color`, `bg`)
4. **Semantic**: Typically applied to header cells, but works in body cells too
