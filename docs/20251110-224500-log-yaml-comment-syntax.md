# Подсветка синтаксиса YAML для YAMT таблиц

**Дата:** 2025-11-10  
**Функция:** Двойной синтаксис для YAMT таблиц с поддержкой подсветки YAML

---

## Проблема

Пользователи хотели иметь подсветку синтаксиса YAML при редактировании YAMT таблиц в Obsidian. 

Оригинальный синтаксис ```yamt не предоставляет подсветку синтаксиса, так как Obsidian не знает, что это YAML. При этом Obsidian не предоставляет публичного API для регистрации языковых алиасов (чтобы сказать "yamt это то же самое, что yaml для подсветки").

---

## Испробованные подходы

### Попытка 1: HTML комментарий `<!-- yamt -->`

**Идея:** Разместить HTML комментарий перед блоком YAML:
```markdown
<!-- yamt -->
```yaml
header:
  - [ "Col1", "Col2" ]
```
```

**Почему не сработало:**  
Obsidian удаляет HTML комментарии при рендеринге Markdown → HTML. К моменту выполнения `registerMarkdownPostProcessor` комментарии уже отсутствуют в DOM.

**Диагностика:** `TreeWalker` с `NodeFilter.SHOW_COMMENT` не находил ни одного комментария.

---

### Попытка 2: Текстовый маркер `-yamt-` перед блоком

**Идея:** Разместить текст на отдельной строке:
```markdown
-yamt-
```yaml
header:
  - [ "Col1", "Col2" ]
```
```

**Почему не сработало:**  
Проблема timing: `registerMarkdownPostProcessor` вызывается до того, как Obsidian полностью отрендерит содержимое code block. Элементы `DIV.el-pre` уже созданы в DOM, но внутри них еще нет `<pre>` и `<code>` элементов.

**Диагностика:**  
- Маркер `-yamt-` успешно находился: `Found -yamt- markers: 1`
- Следующий элемент находился: `DIV.el-pre`  
- Но внутри него было пусто: `has pre inside: false`

Попытки обхода проблемы (поиск по родителям, siblings) не помогли - контент code block просто еще не был отрендерен.

---

### Попытка 3: Автодетект по структуре

**Идея:** Регистрировать processor для всех `yaml` блоков и проверять наличие полей `header`/`body`.

**Проблема:**  
Ложные срабатывания - обычный YAML конфиг может содержать поля `header` или `body`, не являясь таблицей YAMT.

---

## Финальное решение: YAML комментарий `# -yamt-`

### Концепция

Использовать **YAML комментарий** как первую строку блока:

```yaml
# -yamt-
header:
  - [ "Имя", "Возраст" ]
body:
  - [ "Алиса", "30" ]
```

### Почему это работает

1. **Валидный YAML синтаксис** - комментарии игнорируются парсером `js-yaml`
2. **Подсветка синтаксиса** - Obsidian распознает блок как `yaml` и применяет подсветку
3. **Надежная проверка** - используется `registerMarkdownCodeBlockProcessor("yaml", ...)`, который вызывается с доступом к source коду
4. **Простая логика** - проверка первой строки через `string.trim() === '# -yamt-'`
5. **Не зависит от DOM** - работа с source до рендеринга, никаких проблем с timing

### Реализация

```typescript
// Регистрируем processor для yaml блоков
this.registerMarkdownCodeBlockProcessor("yaml", async (source, el, ctx) => {
  // Проверяем первую строку
  const lines = source.split('\n');
  const firstLine = lines[0]?.trim() || '';
  
  const isYamtMarker = firstLine === '# -yamt-' || firstLine === '#-yamt-';
  
  if (isYamtMarker) {
    // Рендерим как YAMT таблицу
    await renderYamtFromSource(source, el, ctx);
  } else {
    // Рендерим как обычный YAML code block
    const pre = el.createEl('pre');
    const code = pre.createEl('code', { cls: 'language-yaml' });
    code.textContent = source;
  }
});
```

### Преимущества

✅ **Полная подсветка синтаксиса YAML** в редакторе  
✅ **Валидный YAML** - комментарий не влияет на парсинг  
✅ **Маркер внутри блока** - не нужна отдельная строка  
✅ **Надежно работает** - не зависит от DOM timing  
✅ **Простая реализация** - проверка одной строки  
✅ **Обратная совместимость** - оригинальный синтаксис ```yamt остается

## Примеры

### Простая таблица

```yaml
# -yamt-
header:
  - [ "Товар", "Количество", "Цена" ]
body:
  - [ "Яблоко", "5", "2.50€" ]
  - [ "Апельсин", "3", "1.80€" ]

### С опциями и стилями

```yaml
# -yamt-
options:
  caption: "Каталог продуктов"
  ariaLabel: "Таблица списка продуктов"

  - [ { data: "ID", width: "50px" }, { data: "Продукт", width: "60%" }, { data: "Статус" } ]

```

  - [ "Данные 1", "Данные 2", "Данные 3" ]

## Технические детали

### Порядок обработки

1. Пользователь создает ```yaml блок с `# -yamt-` в первой строке
2. Obsidian применяет YAML подсветку синтаксиса в Source mode
3. При рендеринге вызывается `registerMarkdownCodeBlockProcessor("yaml", ...)`
4. Плагин проверяет первую строку source
5. Если найден маркер - парсит YAML и рендерит HTML таблицу
6. Если маркера нет - рендерит стандартный code block

### Совместимость

- Оба синтаксиса (`yamt` и `yaml` с комментарием) полностью поддерживаются
- Пользователи могут выбирать вариант по предпочтению
- Обратная совместимость со всеми существующими YAMT таблицами гарантирована

## Выводы

После нескольких итераций и экспериментов с разными подходами, решение с YAML комментарием оказалось наиболее элегантным и надежным. Оно использует стандартные возможности YAML, не требует хаков с DOM, и предоставляет пользователям желаемую подсветку синтаксиса.

Ключевой инсайт: работать с source кодом через `registerMarkdownCodeBlockProcessor` надежнее, чем пытаться манипулировать уже отрендеренным DOM через `registerMarkdownPostProcessor`.
